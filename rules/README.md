# Rule Database

`rules/rules.csv` is the source of truth for reviewed NetCalcKit DNS rules.

Do not edit `sources/curated.txt` or `blocklists/standard.txt` by hand. They are generated by `scripts/build.py`.

## Columns

- `domain` — exact lowercase hostname.
- `vendor` — product or service owner.
- `category` — narrow machine-readable purpose label.
- `evidence_file` — repository evidence record under `evidence/`.
- `false_positive_risk` — `low`, `low-moderate`, `moderate`, or `high`.
- `tier` — minimum list tier: `lite`, `standard`, or `aggressive`.
- `status` — `approved`, `hold`, or `removed`.
- `last_reviewed` — ISO date (`YYYY-MM-DD`) of the latest evidence review.

## Tier model

Tiers are cumulative:

- `lite` rules are eligible for Lite, Standard, and Aggressive.
- `standard` rules are eligible for Standard and Aggressive.
- `aggressive` rules are eligible only for Aggressive.

Only the Standard output is published today. The metadata model is ready for additional tiers without changing the source format.

## Workflow

1. Research a candidate from primary or reproducible evidence.
2. Record the evidence and false-positive assessment under `evidence/`.
3. Add one sorted row to `rules/rules.csv`.
4. Run `python3 scripts/build.py`.
5. Run `python3 scripts/validate.py`.
6. Run unit tests.
7. Verify enforcement in an isolated DNS test environment before release promotion.

A rule being syntactically valid does not make it safe. Compatibility and false-positive evidence still matter.
